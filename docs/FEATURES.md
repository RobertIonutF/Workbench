# Workbench 0.2 feature guide

The desktop, browser UI and CLI share one local Rust runtime. All model responses, tool results and browser assertions come from actual execution. Tests and error messages distinguish configured capabilities from verified ones.

| Feature | How to use it | Behavior and boundary |
| --- | --- | --- |
| Custom model profiles | Connections, then Control center → Models | Save an exact model ID, endpoint, context/output limits, tools/vision capability, sampling/reasoning settings and optional manual prices. Native adapters support OpenAI Chat/Responses, Anthropic and Gemini; compatible local servers include LM Studio and Ollama. A profile is bound to its original endpoint/protocol. |
| Account authentication | Connections | API credentials are destination-bound and DPAPI encrypted on Windows. ChatGPT has a browser OAuth flow. Anthropic uses API credentials; arbitrary provider subscription OAuth is not assumed. Remote MCP public-client OAuth is separate. |
| Capability probes | Models → Probe capabilities | Sends actual text, streaming and structured tool/continuation requests. Evidence records the route and test date. Vision is an explicit capability setting, not inferred from a successful text probe. |
| Model comparison | Control center → Compare | Run the same prompt against selected profiles, inspect responses, latency, usage, assertions and optional tool-round-trip evidence. These requests consume the selected accounts' quota. |
| Usage and budgets | Control center → Usage; task toolbar → Budget | Tracks provider counts or clearly marked estimates, TTFT, latency and manual-price cost estimates. Request/token/cost checks happen before each call; streamed output uses an approximate token guard. Provider billing/tokenization can differ; this is not a billing-enforced financial ceiling. |
| Editor and review | Workspace → files/diffs | CodeMirror language highlighting, multiple open drafts, selection attachment, stale-write checks, side-by-side diff, hashed hunk accept/reject and review comments. Rejection/undo preserves unrelated newer edits or reports a conflict. Acceptance records review; it does not create a commit. |
| Explicit context | Task toolbar → Context | Search bounded file/declaration indexes; attach files, folders, selections, images or PDFs. Inspect actual expanded content/provenance/estimates. Mentions include `@file:src/main.rs`, `@folder:src` and `@symbol:my_function`. The declaration index is lexical, not an LSP or semantic code graph. |
| Images and PDFs | Context upload; MCP tool results | PNG/JPEG/WebP evidence uses each provider's native image dialect with a vision-enabled profile. PDFs contribute extracted text; scanned documents need OCR elsewhere. Attachments are limited to 8 MiB and five images per task. Images returned by MCP tools can also enter model context and the timeline. |
| Task plan | Task toolbar → Plan | Edit a persisted checklist. The agent can update it through `update_plan`; status is not independent evidence of successful tests. |
| Pause, steering and queues | Active task toolbar and composer | Pause at safe model/tool boundaries, resume, steer before the next model request, or queue another turn. Cancellation interrupts cancellable work. Pending tool side effects are not blindly replayed after interruption. |
| Conversation forks | Task toolbar → Fork | Branch the transcript through a selected message. Files remain as they are; review/undo is separate. Incomplete tool transcripts receive an explicit uncertain-outcome marker. |
| Agent teams | Control center → Teams | One to six research/plan/code/review workers using chosen profiles; pipeline evidence handoff or parallel attempts. Research, planning and review withhold mutation authority. Code workers use Ask and separate Git worktrees. Shared budgets are divided across workers. |
| Git isolation | Control center → Git | Create real linked worktrees from committed HEAD. Original uncommitted work stays in its checkout. Review and commit selected files, then integrate a clean worktree into a clean destination. Conflicts and active writers block integration. |
| Pull requests | Control center → Git | Explicit publishing pushes the current committed feature branch to its verified github.com origin and creates a PR through installed/authenticated `git` and `gh`. Workbench isolates publishing from project hooks/config/credential helpers. Use a distinct feature branch and verify the selected repository. |
| Project memory | Control center → Memory | Inspect, edit, disable or remove reusable project notes. Linked worktrees inherit them. Agent-proposed memory always requires approval. Memory is context, not executable authority. |
| Workflow checks | Control center → Workflows | Configure real before-turn, after-write, before-complete or failure commands. Worktrees inherit source-project hooks; execution follows the task policy. Failed completion checks fail the run. Read-only workers report skipped native hooks. |
| Scheduled tasks | Control center → Jobs | Confirm a template, interval, prompt and policy. Each occurrence creates a distinct chat, with Git worktree isolation for writers. Completion/failure notifications link to the resulting task. Durable claims prevent replay of the same occurrence; interrupted schedules require review and re-enabling. |
| Interactive terminal | Control center → Terminal | Real PTY/ConPTY with input, resize, output and stop. Commands have native user authority. Sessions persist while switching pages and stop on app exit. |
| Plugin authoring | Plugins and Plugin Studio | Skill-only, MCP-only or combined packages, Rust/Python/JavaScript templates, build/install/check, source editing, immutable versions and rollback. Ask a configured model to generate actual source, then explicitly inspect/build/install/test it. |
| Plugin debugger | Plugin Studio → Tools | Schema-driven argument forms, actual tools/resources/prompts, saved success/contains/JSON-pointer equality assertions, skill trials, durations, redacted stderr and traces. Unsupported MCP methods report errors. Tests execute declared servers with native authority. |
| Plugin catalog | Plugin Studio → Catalog | Browse three bundled starter plugins or add a pinned GitHub package. Inspect owner/repository/ref/digest, updates and source before installation. Packages are pinned and hash-checked. This is not a hosted, moderated multi-user marketplace. |
| Local browser tests | Plugin Studio → Browser | Start/stop a managed dev server. Launch an isolated headless Edge/Chrome session, fill/click, assert selectors/text and capture screenshots plus console/network failures. Requires an installed supported browser and a loopback application. No personal browser profile is used. |
| Encrypted backups | Plugin Studio → Backups | Passphrase-encrypted AES-GCM portable profile archives contain a consistent SQLite snapshot and encrypted credentials. Restore to a separate profile, or stage current-profile restoration for next startup with a recovery copy. Restored vault entries bind to the destination Windows user. Keep the passphrase separately. |
| Signed updates | Plugin Studio → Updates | Stable/preview manifests are Ed25519 verified with the compiled publisher key; downloads must match the signed SHA-256. The helper waits for app exit, rechecks the file and launches the installer. Trusting another publisher key is explicit. Windows Authenticode signing is a separate publisher-certificate requirement. |
| Background mode | Settings | Keep Workbench in the tray after closing the window. The tray can reopen it or quit, cancel active runs and stop managed processes. Jobs do not run after the application exits. |

## Example setup

1. Add an LM Studio or API connection and test the exact model identifier.
2. Save separate profiles for your fast model and stronger reviewer. Set manual prices only if you want cost estimates, and keep them current yourself.
3. Open a Git project with at least one commit. Attach relevant files and choose a modest request/token budget.
4. Use a pipeline with a read-only planner, an Ask-mode coder and a read-only reviewer. Review approvals and resulting evidence.
5. Inspect hunks and tests, commit reviewed files, then integrate or explicitly publish a pull request.
6. Build a small skill/MCP plugin, exercise its real tool in Studio, save an assertion, and rerun it after changing the implementation.

See [API](API.md) for endpoint contracts, [architecture](ARCHITECTURE.md) for ownership and [verification](VERIFICATION.md) for the checks actually performed.
